# Indexer

The indexer reads crawled markdown files, splits them into retrievable chunks, generates embeddings through Ollama, and writes both text and vectors into PostgreSQL.

## Inputs and Outputs

Input:
- Markdown tree generated by the crawler (typically `../data/markdown`).

Database writes:
- `documents` rows (page metadata + content hash).
- `chunks` rows (chunked markdown, tsvector, embedding vector).

## Requirements

- Go 1.25+
- Reachable PostgreSQL with pgvector extension enabled
- Reachable Ollama endpoint with embedding model available

## Environment Variables

- `DATABASE_URL` (required)
- `OLLAMA_URL` (optional, default `http://localhost:11434`)
- `EMBEDDING_MODEL` (optional, default `nomic-embed-text`)

## Run

Typical run:

```bash
cd indexer
export DATABASE_URL='postgres://<user>:<password>@<host>:5432/splunkdocs'
export OLLAMA_URL='http://127.0.0.1:11434'
go run . -prune ../data/markdown
```

Using helper script:

```bash
cd indexer
./index.sh
```

## Common Flags

- `-prune`: remove database documents whose files are no longer on disk (scoped by product seen in input set).
- `-all-versions`: include superseded patch-version directories; default behavior skips them to reduce duplicate content.
- `-embed-workers`, `-batch-size`, `-parse-workers`, `-write-workers`: throughput tuning.
- `-ollama-url`, `-model`: override embedding backend/model.

## Operational Notes

- Indexing is incremental by content hash.
- If chunking or embedding format changes, a full reindex may be needed.
- The process probes Ollama at startup and exits early on backend failure.
